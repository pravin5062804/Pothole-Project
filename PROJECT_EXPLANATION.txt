1. PROJECT OVERVIEW (Yeh Project Kya Hai?)
--------------------------------------------------------------------------------
Yeh project ek Full-Stack MERN + AI-powered Smart Municipal Civic Issue Reporting 
and Resolution Platform hai.

Iska main goal hai:
- Citizens ko apne locality ke civic issues (potholes, garbage dumping, drainage 
  overflow, streetlight faults, water supply leakage) easily report karne dena.
- Smart AI Vision & Groq LLM se images aur descriptions ko auto-classify karna.
- Turf.js aur MongoDB 2dsphere indexing se duplicate reports ko detect karke 
  ek hi parent ticket me merge karna (taaki municipal department spam na ho).
- Recurrence aur severity ke basis par Dynamic Priority Score calculate karna.
- Municipal Admins ko automatic / manual field worker dispatching provide karna.
- Field workers dwara resolution completion proof (photo + notes) upload karwana.
- Community Verification & Dispute loop: jab tak citizen confirm na kare ya agar 
  dispute ho jaye, ticket reopen hokar elevated priority par chala jata hai.

4. CORE BACKEND LOGIC & ALGORITHMS DEEP DIVE
================================================================================

A. AI VISION & CLASSIFICATION LOGIC (aiService.js):
--------------------------------------------------------------------------------
1. Citizen photo upload karta hai -> backend Groq Llama-3.2-11b-vision model ko call karta hai.
2. AI image & description ko analyze karke JSON return karta hai:
   {
     "category": "pothole | garbage | drainage | streetlight | water | other",
     "confidence": 0.0 to 1.0,
     "severity": "low | medium | high | critical",
     "reasoning": "Explanation..."
   }
3. Agar confidence score 0.70 se kam hota hai, toh system flag kar deta hai:
   needsManualReview = true
4. Agar Groq API unavailable ho, toh smart keyword NLP fallback classifier run hota hai.

B. GEOSPATIAL DEDUPLICATION & CLUSTERING (geoClusterService.js):
--------------------------------------------------------------------------------
Civic systems me ek hi issue ko multiple citizens report karte hain.
1. Jab nayi report aati hai, MongoDB 2dsphere index ke through $near query run hoti hai:
   - Category match honi chahiye.
   - Max distance: 50 meters radius.
   - Status: Active issues only (reported, verified, assigned, in_progress, reopened).
2. Turf.js exact distance calculate karta hai.
3. Agar duplicate match ho jata hai:
   - Naya ticket generate nahi hota.
   - Parent issue ka recurrenceCount increment hota hai (+1).
   - Naye reporter ki info (naam, email, phone) parent issue ke reporters array me jud jaati hai.
   - Nayi photo parent issue me append ho jaati hai.
   - Priority score automatically badha diya jata hai.
   - Deduplication Engine ka log timeline me add hota hai.

C. DYNAMIC PRIORITY SCORING ENGINE (priorityService.js):
--------------------------------------------------------------------------------
Formula:
Priority Score = (Severity Weight * Recurrence Count * 10) + Age Bonus + Dispute Penalty

- Severity Weights: Low = 1, Medium = 2, High = 3, Critical = 4
- Dispute Penalty: Agar resolution dispute ho gaya hai, +25 score add hota hai taaki field worker turant dobara kaam kare.

D. 3-TIER RESOLUTION VERIFICATION & DISPUTE LOOP (verificationController.js):
--------------------------------------------------------------------------------
1. Field Worker kaam complete karke completion photo upload karta hai.
2. Status badal kar 'pending_confirmation' ho jata hai aur 3-day verification window start hoti hai.
3. Citizen ko real-time notify kiya jata hai.
4. Agar Citizen 'Confirm' vote karta hai -> Status 'resolved' ban jata hai.
5. Agar Citizen 'Dispute' vote karta hai (kaam theek se nahi hua) -> 
   Status 'reopened' ban jata hai, disputedResolution = true ho jata hai, 
   aur Priority Score elevate hokar ticket wapas queue me chala jata hai.


================================================================================
5. END-TO-END USER FLOW (Ticket Lifecycle)
================================================================================

Step 1: Citizen Report Karta Hai
- Citizen Report page par photo upload karta hai aur GPS location set karta hai.
- AI category aur severity auto-suggest karta hai.

Step 2: Backend Deduplication & Creation
- Backend check karta hai ki 50 meter ke radius me same issue already hai ya nahi.
- Duplicate mila -> Merge hota hai aur recurrence badhta hai.
- Naya mila -> Naya ticket banta hai (CR-2026-XXXX) with status 'reported'.

Step 3: Admin Review & Worker Dispatch
- Admin Dashboard par ticket visual hota hai with Priority Score.
- Admin auto-dispatch ya manual assignment ke through field worker ko ticket assign karta hai ('assigned').

Step 4: Field Worker Execution
- Worker ko taskboard par ticket dikhta hai with map navigation.
- Worker status 'in_progress' karta hai.
- Kaam hone par completion photo upload karta hai ('pending_confirmation').

Step 5: Citizen Verification
- Citizen live tracking page par resolution proof dekhta hai.
- Citizen Confirm karta hai -> 'resolved'.
- Citizen Dispute karta hai -> 'reopened' with high priority.
